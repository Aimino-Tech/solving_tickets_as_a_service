# Linear Tickets — Hermes Agent Feature Integration

## Ticket 1: Self-Hosted Scheduler Service

**Project**: Hermes Agent — Feature Integration
**Priority**: Medium
**Labels**: infra, automation, campaign

**Problem**: The Hermes agent needs a self-hosted cron/scheduler that can reliably fire posts at scheduled times (e.g., Twitter threads on specific dates). The current gateway.json heartbeat tasks work for polling/monitoring but cannot schedule one-shot future posts.

**Proposed solution**: Deploy a lightweight scheduler (e.g., `hermes cron` daemon or a standalone cron container) on a cheap VPS (~$5/mo). The scheduler reads `config/cron-jobs.yaml` and fires jobs at their scheduled times.

**Constraints**:
- Must handle one-shot schedules (not just recurring)
- Must support platform-specific auth (Twitter API tokens, etc.)
- Should log execution results to DuckDB
- Budget: $0-5/mo recurring

**Blockers**: Server cost approval, domain/DNS if needed.

## Ticket 3: LinkedIn Auto-Posting (Reach-Optimized)

**Project**: Hermes Agent — Feature Integration
**Priority**: Low
**Labels**: skill, linkedin, automation

**Problem**: LinkedIn penalizes posts with links in the body. Automated posting tools typically put links in post body, which kills reach. The optimal pattern is "link in first comment" which most automation tools don't support.

**Proposed solution**:
1. Research LinkedIn API capabilities for comment posting alongside article/post creation
2. If API supports comments: build a LinkedIn posting skill that posts body → posts link comment
3. If API doesn't support cross-posting: accept LinkedIn remains manual-only
4. Alternative: LinkedIn carousel (PDF upload) which doesn't have the link penalty

**Success criteria**: Can post a LinkedIn article + automatically add a link comment. Or decision documented that LinkedIn stays manual.

**Blockers**: LinkedIn API restrictions on automated content, reach penalty for link-in-body.

## Ticket 4: Hacker News Show HN Workflow

**Project**: Hermes Agent — Feature Integration
**Priority**: Medium
**Labels**: process, hn, campaign

**Problem**: Hacker News has a strict anti-LLM policy (dang's 2026 rule). Show HN submissions and comments must not be generated by LLMs. This means HN posting cannot be automated — it must be a human-written, manual submission.

**Proposed solution**:
1. Document the manual HN submission checklist in the campaign playbook ✅ (done in playbook update)
2. Create a "Show HN prep" template that collects facts + data for human drafting
3. The agent can prepare a research brief (benchmarks, architecture details, open source stats) for the human to use as source material
4. The human writes the title + first comment from those facts
5. Set calendar reminder for Show HN day

**Success criteria**: A repeatable workflow where the agent preps research and the human writes the submission. Documented in playbook as standard procedure.

**Non-blocker**: This is intentional — HN quality > automation.
