Engineering OpenCode

How SYNTARO Uses OpenCode to Fix Real-World Bugs

AT AImino Team July 15, 2026 · 7 min read

SYNTARO doesn't just label issues and hope for the best. Under the hood, every fix is powered by OpenCode — the 162K★ open-source coding agent. This post explains the integration architecture, the fix pipeline, and the quality gates that ensure every PR is production-ready.

Architecture Overview

When a GitHub issue is labeled with syntaro:fix, here's what happens:

GitHub Issue (labeled syntaro:fix)
       │
       ▼
  Webhook Server (Express/Node.js)
       │
       ├── Verify signature
       ├── Post "working on it" comment
       ├── Build prompt from issue context
       │
       ▼
  OpenCode Agent (via HTTP API)
       │
       ├── Clone repo into E2B sandbox
       ├── Investigate root cause
       ├── Write fix + regression tests
       ├── Run test suite
       ├── Commit & push branch
       │
       ▼
  GitHub API
       │
       ├── Open draft PR
       └── Post result comment

The entire pipeline runs in under 4 minutes for typical fixes.

The OpenCode Integration

OpenCode is a general-purpose coding agent that can clone repositories, navigate codebases, make changes, run tests, and commit results. SYNTARO communicates with OpenCode via its HTTP API on port 4096.

Prompt Engineering

The key to SYNTARO's accuracy is how we construct the prompt. For each issue, we build a context-rich prompt that includes:

  • The full issue title and body
  • Repository structure overview (key files and directories)
  • Error logs and stack traces from the issue
  • Similar past fixes for pattern matching
  • Test runner configuration and expected test commands

This structured context helps OpenCode understand the codebase before making any changes.

Sandbox Isolation with E2B

Every fix runs in an isolated E2B sandbox. The sandbox provides:

  • A full Linux environment with common developer tools
  • Network access for dependency installation
  • Runtime support for Node.js, Python, Go, Rust, and more
  • 10-minute timeout per fix with graceful cleanup
  • Ephemeral storage — destroyed immediately after execution

No two fixes share a sandbox. No data persists between runs. Your code is never stored on SYNTARO servers.

The 6 Quality Gates

The most important part of SYNTARO is what happens after OpenCode writes the fix. Before a PR is created, every fix passes through 6 gates:

Gate 1: Reality Check

We verify every file referenced in the fix actually exists in the repository. This catches hallucinations where the agent invents file paths.

Gate 2: Compile Check

For TypeScript projects, we run tsc --noEmit. For other languages, we run the equivalent compile step. If the code doesn't compile, the fix is rejected.

Gate 3: Test Integrity

We check that tests contain real assertions. This prevents "vacuous tests" that pass without testing anything meaningful.

Gate 4: Hallucination Scan

We scan for telltale signs of hallucinated code: TODO stubs, placeholder implementations, fake imports from non-existent packages, and impossible API calls.

Gate 5: Dead Code Check

We use knip and ts-prune to verify there are no orphaned exports or unused files introduced by the fix.

Gate 6: MCI Verification

Message-Code Inconsistency (MCI) scoring checks that the PR description accurately describes what the diff actually does. A low MCI score means the fix is flagged for human review.

Performance Numbers

After processing thousands of issues across hundreds of repositories, here's what we've measured:

  • 3.2 minutes — Average time from label to PR
  • 87% — First-try CI pass rate
  • 58% — Fixes accepted without any human edits
  • 42% — Fixes that needed some human modification (but still saved 80%+ of the work)
  • < 1% — False positive rate (fixes that broke something unrelated)

Running OpenCode Locally

If you're interested in the underlying agent, you can run OpenCode locally:

# Install OpenCode
npx opencode init

# Start the agent server
opencode serve --port 4096

# Test with a sample issue
curl -X POST http://localhost:4096/execute \
  -H "Content-Type: application/json" \
  -d '{"task": "Fix the null pointer in src/user.ts"}'

OpenCode also supports custom models, tools, and skill configurations. See the OpenCode documentation for details.
