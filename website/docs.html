Quick Start

Get SYNTARO running on your repository in under 5 minutes.

Prerequisites

  • A GitHub account with admin access to a repository
  • Node.js 22+ (for self-hosting)
  • OpenCode CLI (for self-hosting)

One-Command Setup

The fastest way to get started:

git clone https://github.com/tamnguyen08/solving_tickets_as_a_service
cd solving_tickets_as_a_service
npm run init

This will install dependencies, create a .env file, and guide you through the setup wizard.

Install the GitHub App

1. Go to the SYNTARO GitHub App page.

2. Click Configure → select your repository.

3. Label an issue with syntaro:fix and watch SYNTARO work.

Tip: The hosted version requires no infrastructure. Just install the app and label issues. Self-hosting is only needed if you want full control.

Manual Setup

1. Clone & Install

git clone https://github.com/tamnguyen08/solving_tickets_as_a_service
cd solving_tickets_as_a_service
npm install

2. Start OpenCode

OpenCode is the AI agent backend. Start it in a separate terminal:

opencode serve --port 4096

3. Configure Environment

cp .env.example .env
# Fill in: GITHUB_APP_ID, GITHUB_APP_PRIVATE_KEY, GITHUB_WEBHOOK_SECRET

4. Seed Database

npx tsx src/db/seed.ts

5. Run

npm run dev

Verify with: curl http://localhost:3000/health

Configuration

SYNTARO is configured via environment variables. Key settings:

VariableRequiredDescription
GITHUB_APP_IDYesYour GitHub App ID
GITHUB_APP_PRIVATE_KEYYesGitHub App private key (PEM)
GITHUB_WEBHOOK_SECRETYesWebhook secret
OPENCODE_URLNoOpenCode server URL
OPENCODE_MODELNoAI model to use
LOG_LEVELNodebug | info | warn | error
PORTNoServer port (default: 3000)

Issue Labels

SYNTARO responds to the following issue labels:

LabelAction
syntaro:fixAutomatically investigate, fix, and open a PR
syntaro:investigateInvestigate and report findings without making changes
syntaro:refactorRefactor code with no functional changes
syntaro:docsGenerate or update documentation

Docker Deployment

# Build
docker build -t syntaro-bot .

# Run
docker run -p 3000:3000 \
  -e GITHUB_APP_ID=your_id \
  -e GITHUB_APP_PRIVATE_KEY="$(cat your-private-key.pem)" \
  -e GITHUB_WEBHOOK_SECRET=your_secret \
  syntaro-bot

Security: Use --read-only --tmpfs /tmp in production for read-only root filesystem.

Fly.io Deployment

SYNTARO includes a fly.toml in the root directory. Deploy with:

# Install Fly CLI
curl -L https://fly.io/install.sh | sh

# Deploy
fly launch
fly secrets set GITHUB_APP_ID=...
fly secrets set GITHUB_APP_PRIVATE_KEY="$(cat key.pem)"
fly secrets set GITHUB_WEBHOOK_SECRET=...
fly deploy

Railway Deployment

SYNTARO includes a railway.json config. Deploy on Railway:

# Install Railway CLI
npm install -g @railway/cli

# Deploy
railway login
railway init
railway up

Set environment variables in the Railway dashboard.

API Reference

SYNTARO exposes a REST API for managing issues, checking status, and more.

Health Check

GET /health

Returns {"status":"ok","timestamp":"..."} when the service is running.

Webhook Handler

POST /api/github/webhook

Handles GitHub webhook events (issue labeling, push events, etc.). Requires X-Hub-Signature-256 header for verification.

Issue Status

GET /api/issues/:owner/:repo/:number

Returns the current status of a SYNTARO-managed issue.

Webhooks

SYNTARO uses GitHub webhooks to listen for issue events. Configure your GitHub App with these webhook events:

  • Issues — label changes trigger fixes
  • Issue comment — for interactive workflows
  • Push — to sync repository state
  • Pull request — to track PR status

Sandbox Environment

Each SYNTARO fix runs in an isolated sandbox powered by E2B. The sandbox includes:

  • Full Linux environment with common developer tools
  • Network access for dependency installation
  • Runtime support for Node.js, Python, Go, Rust, and more
  • 10-minute timeout per fix
  • Ephemeral storage — destroyed after execution

FAQ

Does SYNTARO work with monorepos?

Yes. SYNTARO detects your project structure and works with any monorepo configuration. It reads your existing package manager and test runner configuration.

Can I customize the fix prompt?

Advanced users can customize the agent prompt via the OPENCODE_CONFIG environment variable. See the GitHub repo for examples.

What happens if the fix breaks tests?

SYNTARO will flag the PR as failing and leave a detailed comment explaining what went wrong. The issue remains open until a human addresses it.

Does SYNTARO support GitHub Enterprise Server?

Self-hosted SYNTARO can be configured to work with GHES. Contact sales@aimino.io for setup assistance.

Troubleshooting

SYNTARO doesn't respond to my label

Check that: (1) the GitHub App is installed on your repo, (2) the webhook is configured correctly, (3) the issue has the exact label syntaro:fix (case-sensitive).

Fix fails with a timeout

Large codebases may exceed the default sandbox timeout. Consider upgrading to a Team or Enterprise plan for longer timeouts, or self-host with a custom timeout setting.

How do I update SYNTARO?

For the hosted version, updates are automatic. For self-hosted: git pull && npm install && npm run build && npm run start.
