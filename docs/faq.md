# FAQ

## Security

**Q: Does STAS have access to my private code?**
A: Only when you install the GitHub App or run the GitHub Action. STAS clones your repo into an ephemeral sandbox that is destroyed after the fix is generated. We never store your code. For self-hosted users, your code never leaves your infrastructure.

**Q: Can STAS be used for malicious purposes?**
A: STAS is designed with multiple security layers: prompt injection sanitization (strips known injection patterns from issue text), sandbox isolation (Docker containers with network restrictions), GitGuard (blocks destructive git operations), and least-privilege GitHub App permissions.

**Q: Is STAS safe to install on my organization's repos?**
A: STAS requests minimum GitHub permissions (`contents: write` for creating PRs, `issues: read` for reading issues). All agent actions are logged. You can uninstall at any time.

## Code Ownership

**Q: Who owns the fix PR generated by STAS?**
A: You do. STAS is a tool that generates a pull request in your repository. The PR is authored by a bot account, but you retain full ownership and control. You review, modify, and merge the PR on your terms.

**Q: Does STAS claim any rights to the generated code?**
A: No. STAS is MIT-licensed open-source software. The generated fix code belongs to the repository owner, governed by the repository's license.

## Quality

**Q: How do I know the fix is correct?**
A: Every STAS PR includes a collapsible quality report section showing:
- ✅/❌ Reality Check — all referenced files exist
- ✅/❌ Compile Check — TypeScript compiles without errors
- ✅/❌ Test Integrity — tests have real assertions
- ✅/❌ Hallucination Scan — no fake imports or placeholder stubs
- ✅/❌ Dead Code Check — no orphaned files or unused exports
- ✅/❌ External AI Tool Scan — no hallucinated packages or phantom APIs

If any gate fails, the report shows exactly what failed and why.

**Q: How do I know STAS is not making things up?**
A: STAS runs 6 quality gates on every fix. Each gate is a deterministic check — not a model call. Files are checked for existence, code is compiled, tests are run for real. Hallucination detection scans for fake imports, placeholder stubs, and phantom API calls.

## Frameworks & Languages

**Q: Does STAS work with Python?**
A: Yes. STAS supports Python, TypeScript/JavaScript, Go, Rust, Ruby, Java, PHP, Swift, Dart, Elixir, C++, and .NET.

**Q: Does STAS work with monorepos?**
A: Yes, with some caveats. STAS detects monorepo tools (Turborepo, Nx) and uses the appropriate test command. For best results, ensure your test suite can be run from the repo root.

**Q: Does STAS work with non-GitHub repos?**
A: STAS primarily supports GitHub. GitLab and Bitbucket are in beta — see [Platforms documentation](platforms/README.md).

## Troubleshooting

**Q: I labeled an issue but nothing happened**
A: Check [Troubleshooting](troubleshooting.md). Common causes: webhook not reaching STAS, label name mismatch, or OpenCode not running.

**Q: The fix PR has a failing quality gate**
A: That's by design — transparency builds trust. Read the gate details in the PR body. Common issues: test environment differences, missing dependencies, or the fix introduced a real compilation error.

**Q: Can I customize the label that triggers STAS?**
A: Yes. Set the `STAS_LABEL` environment variable to your preferred label name. Default is `stas:fix`.

## General

**Q: Is STAS open source?**
A: Yes. STAS is MIT-licensed. The full source is available at [github.com/Aimino-Tech/solving_tickets_as_a_service](https://github.com/Aimino-Tech/solving_tickets_as_a_service).

**Q: How is STAS different from GitHub Copilot?**
A: Copilot generates code inline as you type. STAS is a bot that reads an issue, investigates your codebase, writes a fix, runs tests, and opens a PR — end-to-end automation.

**Q: How is STAS different from Plip or KintsugiBot?**
A: See the [Competitive Comparison](https://stas.dev/benchmark) page. STAS's key differentiators: 6 quality gates verify every fix, open-core model (self-host or cloud), and AGI-powered investigation.
