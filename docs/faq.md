# FAQ

## Security

**Q: Does SYNTARO have access to my private code?**
A: Only when you install the GitHub App or run the GitHub Action. SYNTARO clones your repo into an ephemeral sandbox that is destroyed after the fix is generated. We never store your code. For self-hosted users, your code never leaves your infrastructure.

**Q: Can SYNTARO be used for malicious purposes?**
A: SYNTARO is designed with multiple security layers: prompt injection sanitization (strips known injection patterns from issue text), sandbox isolation (Docker containers with network restrictions), GitGuard (blocks destructive git operations), and least-privilege GitHub App permissions.

**Q: Is SYNTARO safe to install on my organization's repos?**
A: SYNTARO requests minimum GitHub permissions (`contents: write` for creating PRs, `issues: read` for reading issues). All agent actions are logged. You can uninstall at any time.

## Code Ownership

**Q: Who owns the fix PR generated by SYNTARO?**
A: You do. SYNTARO is a tool that generates a pull request in your repository. The PR is authored by a bot account, but you retain full ownership and control. You review, modify, and merge the PR on your terms.

**Q: Does SYNTARO claim any rights to the generated code?**
A: No. SYNTARO is MIT-licensed open-source software. The generated fix code belongs to the repository owner, governed by the repository's license.

## Quality

**Q: How do I know the fix is correct?**
A: Every SYNTARO PR includes a collapsible quality report section showing:
- ✅/❌ Reality Check — all referenced files exist
- ✅/❌ Compile Check — TypeScript compiles without errors
- ✅/❌ Test Integrity — tests have real assertions
- ✅/❌ Hallucination Scan — no fake imports or placeholder stubs
- ✅/❌ Dead Code Check — no orphaned files or unused exports
- ✅/❌ External AI Tool Scan — no hallucinated packages or phantom APIs

If any gate fails, the report shows exactly what failed and why.

**Q: How do I know SYNTARO is not making things up?**
A: SYNTARO runs 6 quality gates on every fix. Each gate is a deterministic check — not a model call. Files are checked for existence, code is compiled, tests are run for real. Hallucination detection scans for fake imports, placeholder stubs, and phantom API calls.

## Frameworks & Languages

**Q: Does SYNTARO work with Python?**
A: Yes. SYNTARO supports Python, TypeScript/JavaScript, Go, Rust, Ruby, Java, PHP, Swift, Dart, Elixir, C++, and .NET.

**Q: Does SYNTARO work with monorepos?**
A: Yes, with some caveats. SYNTARO detects monorepo tools (Turborepo, Nx) and uses the appropriate test command. For best results, ensure your test suite can be run from the repo root.

**Q: Does SYNTARO work with non-GitHub repos?**
A: SYNTARO primarily supports GitHub. GitLab and Bitbucket are in beta — see [Platforms documentation](platforms/README.md).

## Troubleshooting

**Q: I labeled an issue but nothing happened**
A: Check [Troubleshooting](troubleshooting.md). Common causes: webhook not reaching SYNTARO, label name mismatch, or OpenCode not running.

**Q: The fix PR has a failing quality gate**
A: That's by design — transparency builds trust. Read the gate details in the PR body. Common issues: test environment differences, missing dependencies, or the fix introduced a real compilation error.

**Q: Can I customize the label that triggers SYNTARO?**
A: Yes. Set the `SYNTARO_LABEL` environment variable to your preferred label name. Default is `syntaro:fix`.

## General

**Q: Is SYNTARO open source?**
A: Yes. SYNTARO is MIT-licensed. The full source is available at [github.com/Aimino-Tech/solving_tickets_as_a_service](https://github.com/Aimino-Tech/solving_tickets_as_a_service).

**Q: How is SYNTARO different from GitHub Copilot?**
A: Copilot generates code inline as you type. SYNTARO is a bot that reads an issue, investigates your codebase, writes a fix, runs tests, and opens a PR — end-to-end automation.

**Q: How is SYNTARO different from Plip or KintsugiBot?**
A: See the [Competitive Comparison](https://syntaro.dev/benchmark) page. SYNTARO's key differentiators: 6 quality gates verify every fix, open-core model (self-host or cloud), and AGI-powered investigation.
